# Alfred 1.1.0 preview — conversational travel planning

A product of **Life on our Trails**.

Start a trip with dates, a budget or a craving. A destination is no longer
required before discovery. Alfred asks progressively, compares up to three
places, explains its choices and waits for your selection before building an
itinerary. Chat, drafts, preferences and background research survive restarts.

## Try it

Open **Travel Planner** and enter:

> I have holiday from 2 October to 5 October. Budget is ₹15,000. Suggest me somewhere.

Confirm your starting city, compare destinations and choose one. Select **Build
itinerary**, then try **Day 2 is too busy. Make it relaxed.** Choose **Save Travel
Plan** to retain the itinerary and conversation. **Save draft** works before you
have a destination. Edit learned preferences in **Settings → Travel Preferences**.

This release also adds evidence and freshness details, budget breakdowns,
vehicle-aware estimates, optional post-trip feedback, and reviewable associations
between uploaded trip photos and saved plans. Photo learning is optional; photo
counts are never treated as proof that you liked a place.

## Current coverage

The conversation engine uses local structured intents and an initial catalogue
of 13 Indian destinations. It is not a general-purpose language model or a
worldwide destination search. No new model credentials are required.

Live weather uses the existing public forecast integration. Deep Research can
collect news leads, but a headline is not verification of current access. Route
distances, travel times and costs are estimates. Live hotels, train/flight
availability, turn-by-turn routing and comprehensive permit/closure verification
are not integrated. Sources expose these limits rather than inventing fresh facts.

See the [planner guide and configuration](https://github.com/sourabh48/alfred_ai/blob/master/docs/TRAVEL_PLANNER.md)
for supported requests, privacy, provider coverage and verification commands.

## Install or update

Run **ALFRED-Setup.exe** for per-user Windows x64 installation, desktop shortcuts
and an uninstaller. Python, Docker and Redis are not required for this native
package. For portable use, extract the complete ZIP and open **ALFRED Launcher.exe**.

Back up your data and stop Alfred before updating. Existing travel records and
fields are retained; migration `0009` allows empty destinations and dates for
drafts. Downgrading to an older executable after creating drafts requires a
consistent pre-upgrade data backup.

The default installed data folder is `%LOCALAPPDATA%\ALFRED`. A source checkout
can use a different folder; installation does not merge those accounts.
Uninstalling retains saved data. The Windows tray icon and offline illustrated
installation guide remain included.

This preview installer is unsigned. **SHA256SUMS.txt** and
**release-manifest.json** identify the packaged files; they are not digital
signatures or copy protection. Clean second-PC installation/reboot, human
screen-reader acceptance and sustained scheduled-business-outcome observation
remain open. ALFRED remains a local/LAN application.
